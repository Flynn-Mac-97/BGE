# Comment style

- Explain why, not what the code already says.
- Keep comments short and true.
- Every word costs a token; the reader is usually an agent. Cut any word doing no work.
- Say it straight: no metaphor, no analogy, no story. State the fact and the reason.
- Literal verbs. A file is in a directory, not "sitting" there; a value is stored, not "living" somewhere. Many different models read this text — write for the least capable one.
- Never use a long word where a short one works. Active voice. Cut every word that can be cut.
- Delete comments that no longer match the code.
- A project may replace this rule for its own files.
